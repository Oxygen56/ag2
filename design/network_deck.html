01 / The shape of the internet

The internet is shaped for resources.

HTTP, REST, MCP — every layer assumes the request is stateless, idempotent, replicable, addressable.

This shape is right when the clients hold the state. A human remembers what they just sent and what to do with the reply. A browser caches. A workflow hardcodes the next transition. The network can be stateless because the endpoints aren't.

Resources are the right primitive when the thing on the other end is a stateful brain or a deterministic program. Forty years of network design followed from that assumption.

02 / The mismatch

Agents break the assumption.

An LLM is stateless. Its output is stochastic. Neither end of a conversation behaves like the client or the server the protocols were drawn for.

What an agent actually is

Every memory is re-injected as context — there is no persistent "brain" between turns. Generation is a probability distribution, not a function. Identity exists only as long as someone hands you the right prompt prefix. Side effects (a sent message, a file written, a payment authorised) are real even when the next call doesn't know they happened.

What today's frameworks do about it

They become single‑process orchestrators. LangGraph holds the state in a graph snapshot. CrewAI holds it in a Crew. AutoGen holds it in an actor runtime. The orchestrator is the missing brain — the agents themselves stay stateless, and the network underneath is still a request/response wire.

What that costs

The moment two agents need to live in different processes, on different machines, in different organisations, on different schedules — the orchestrator's grip slips. State that used to live in one Python object now has nowhere to live. The wire format (A2A, MCP) is still resource‑shaped. Distributed multi‑agent reduces to "more REST calls."

03 / The definition

Action‑driven networking is the missing layer.

A network where the channel between agents is the unit of abstraction — not the request, not the orchestrator, not the team.

The internet's resource layer keeps doing its job: agents fetch documents, call MCP tools, hit REST endpoints. Action‑driven networking is what sits next to that — the substrate for interactions that are stateful by nature, that imply identity, that carry consequences. The channel is the durable contract: it carries history, participants, the protocol they're following, and the liveness expectations that hold them to it.

Plainly: MCP is HTTP for tools. A2A is HTTP for agents. AG2 Network is TCP for actions. The layer where stateful, identity‑bound, choreographed interaction lives — independent of which framework wrote the agent above it or which provider serves its tokens.

04 / The stack

Seven layers, each independently replaceable.

Every layer is a Protocol, not a class. Swap a transport, plug a new adapter, register a new view — the rest of the stack doesn't notice.

The framework was drawn as a stack so that each concern has one home and one substitutable shape. Transport doesn't know about workflows. Workflows don't know about transports. Identity doesn't know about tools. Tools don't know about identity. That separation is what makes the same code run in‑process for a unit test, across processes for a deployment, and across organisations for federation — without rewriting the layer above or below.

The hub is in L2. It is a router, not an orchestrator. It never calls Agent.ask, never executes tenant code, never makes the next‑turn decision. Choreography lives in L3, computed by a stateless adapter from WAL‑folded state. The trust boundary runs through L6.

05 / Identity

Identity is three records, not a name.

A bare agent is anonymous. Joining the network stamps a permanent identifier, attaches a track record, and publishes a usage doc the calling LLM can read.

Passport

Immutable identity

Hub‑stamped UUID7 at registration. Carries name, owner, provider, model, cost profile, region, signed AuthBlock. Re‑registering produces a new identity.

read by
hub, billing, auth, routing
mutation
never (for the life of the registration)
Resume

Mutable track record

Self‑claimed capabilities, domains, summary, examples. Plus hub‑observed counters: completed, failed, p50 latency. Discovery ranks by observed, not just declared.

read by
discovery, planning LLMs, peers
mutation
tenant set + hub observation
SKILL.md

LLM‑facing doc

Anthropic‑format Markdown with frontmatter. Lists when to call this agent, inputs expected, examples. The same format 30+ tools already read — the discovering LLM uses it like any other skill.

read by
peer LLMs deciding who to call
mutation
author rewrites the file

Why split into three.

Three different readers, three different mutation rates, three different trust models. Conflating them — the way agent.name = "Engineer" does in every classic framework — means you cannot distinguish who the agent is (passport) from how it has performed (resume) from how to call it (skill).

Discovery becomes capability‑ranked by observed outcomes, not name‑based or author‑asserted. Federation becomes possible: a signed passport from another hub is cryptographically the same kind of thing as one from yours.

06 / Channels

The channel is the action.

A durable, identity‑scoped, protocol‑typed container with an append‑only WAL. Open it, work inside it, close it — the channel is what survives.

Manifest (data) + Adapter (code)

A ChannelManifest is the persisted description of what the channel is — type, version, participant schema, view policy, declared expectations. A ChannelAdapter is the code that defines its choreography: stateless, pure, registered by (type, version).

State by folding, not by storing

The hub holds no choreography state of its own. AdapterState is fold(env_n, fold(env_{n−1}, ... initial)) — a deterministic projection of the WAL. validate_send and on_accepted are O(1). Restart and re‑fold from disk and you are back where you were, exactly.

Audience addressing

Every envelope carries an audience: a subset of participants who actually see it, or None for broadcast. The WAL records all; the projection per participant filters by visibility. Private side‑channels and group context live on the same primitive.

Four built‑in choreographies on the same primitive.

consulting

1 ↔ 1, one round

Strict Q+R. Initiator asks, respondent answers, the channel auto‑closes. The simplest delegation primitive.

conversation

1 ↔ 1, multi-turn

Bidirectional, long‑running. Either side may speak. Closes on explicit close or TTL. Default view bounds the prompt by windowing.

discussion

N‑party turn‑taking

Round‑robin, dynamic, or static ordering. Multi‑party N‑of‑M quorum on the invite handshake. Per‑participant windowed views keep prompts bounded.

workflow

Orchestrated by a graph

Speaker advances per a declarative TransitionGraph over folded state. Replaces the classic GroupChat + Handoffs + AfterWork triad with a single channel kind.

+ extensible

Bring your own choreography

The Adapter Protocol is open. Tournament, auction, broadcast, notification — any choreography fits if it can be written as a pure fold + validate + on_accepted triple.

invariant

WAL is the truth.

Every channel has an append‑only WAL. Hub crashes? Replay. Process moves machines? Replay. New observer joins mid‑flow? Project from the WAL. The channel is the contract; the WAL is its memory.

07 / Durability

What survives, survives exactly.

Every channel writes an append‑only log. Every adapter state is a pure fold of that log. Crash the hub, re‑fold from disk, and the channel is exactly where it was — to the envelope.

The substrate, not a feature

Frameworks that came before treat durability as an opt‑in extension. LangGraph attaches a checkpointer; the Durable Workflow extension bolts onto AutoGen. Both exist because the default in‑memory orchestrator state is famously fragile in production. AG2 Network inverts the default — durability is the substrate.

"Exactly" means exactly

Adapter state is fold(envn, … fold(env1, initial)) — a pure function. Same WAL on disk, same state in memory, every time. No migration step, no replay‑the‑replay loop, no "best effort." A hub restart is a non‑event for the channels it hosts; the in‑flight workflow picks up at the next envelope.

Even orchestration is data

Workflow graphs are JSON snapshotted into the channel manifest. Targets and conditions resolve through a named registry. No Python travels the wire; TransitionGraph.dumps() on one side and loads() on the other yields the same graph, same fold, same outcome. Migration from imperative orchestrators is mechanical — from_classic_pattern translates classic AG2 patterns directly into the same data shape.

Tasks have their own durable spine

A task is an agent‑owned event stream — TaskStarted, TaskProgress, terminal — appended as it happens. Opt into Task.checkpoint(state) and the work itself becomes resumable from the last checkpoint, on the same machine or a different one.

Why this matters in deployment. Channels run for hours. Processes restart, machines reboot, networks partition, humans go off shift, deploys ship mid‑flight. Without durability as substrate every one of those events ends the channel. With it, the channel is the artifact that outlasts everything beneath it — visible to ops, replayable for debugging, auditable for compliance, available to any new participant who joins mid‑flow.

08 / Choreography

Choreography you can dial in.

From an open multi‑party discussion to a fully declared workflow — the same channel primitive, the same fold semantics. Choose your level of control; mix when the work calls for it.

Why choreography is the right default

When agents decide their next move from a local view of a shared, durable log rather than from a central conductor, the properties you actually want for multi‑agent work fall out by construction:

  • No bottleneck. No conductor means no single point of latency or failure. The channel scales with participants, not with an engine.
  • Parallelism is the default. Multi‑party fan‑out happens at the network, not in user code.
  • Cross‑process by construction. No shared orchestrator state means participants live wherever convenient — same process, different machine, different continent.
  • Human as peer. A person is just another participant with a different reply latency. HITL is structural, not bolt‑on.
  • Resumable by construction. Each turn is recomputed from the WAL projection; restart any participant and they pick up where they left off.

Controlled choreography — the spectrum

Pure choreography is loose; full orchestration is rigid. Real multi‑agent work lives somewhere in between, and which point depends on the task. The framework treats this as a dial, not a fork in the road — every position on the dial is the same channel primitive with a different adapter, or the same adapter with a different knob.

Where to dial.

The strict end, in one snippet.

When you reach for the fully‑declared end of the spectrum, the workflow adapter is what runs it — one channel, one declarative graph, the same fold semantics every other adapter uses. Targets and conditions are pure resolvers over (state, envelope); the hub stays a router. This is what replaces classic AG2's GroupChat + Handoffs + AfterWork triad. 

graph = TransitionGraph(
  initial_speaker="triage",
  transitions=[
    Transition(when=ToolCalled("transfer_eng"),   then=AgentTarget("eng")),
    Transition(when=ToolCalled("transfer_legal"), then=AgentTarget("legal")),
    Transition(when=FromSpeaker("eng"),                then=RevertToInitiatorTarget()),
    Transition(when=FromSpeaker("legal"),              then=RevertToInitiatorTarget()),
  ],
  default_target=TerminateTarget("triage_done"),
  max_turns=20,
)

await client.open(type="workflow", target=["eng", "legal"], knobs={"graph": graph.dumps()})

09 / Federation & bidirectional streaming

One surface — in‑process, across‑process, across‑org.

The same channel runs between two agents in one Python process or two agents on two continents in two companies. Federation and omni‑modal streaming are extensions of the same Protocol, not retrofits.

Multi‑hub federation

Each organisation runs its own hub. Identity is signed at the source. A signed Passport from another hub is cryptographically the same kind of thing as one from yours. The HubArbiter's resolve_unknown_audience seam decides routing: an envelope addressed to "db-vendor-agent" resolves to "forward to peer hub at the partner org."

NetworkChangedFrame propagates registration and resume changes across the federation the way BGP propagates routes. Hubs gossip their capability indexes; clients cache and invalidate on push.

The result: a channel can span two hubs. Participants on each side see the same WAL projection. The choreography adapter doesn't know or care which hub holds the channel's primary WAL — federation just renames the routing target.

Omni‑modal bidirectional streaming

Transient ChunkFrames reference a parent envelope and carry a sender‑monotonic sequence number. They flow through the same fan‑out path the hub uses for any other delivery, and the receiver's ChunkSubscription demuxes them by (channel_id, parent_id).

Text tokens stream the same way audio frames stream the same way image patches stream the same way video frames stream — the chunk is opaque payload at the transport layer; the view policy and the receiving client decide how to surface it. The WAL only records finalised envelopes; chunks live and die in‑flight.

Bidirectional is just two subscriptions. The same channel that streams an analyst agent's spoken commentary to a researcher's headset also streams the researcher's voice annotations back to the analyst. The channel doesn't have a privileged direction.

10 / Demo · production incident

A real incident, choreographed.

02:14 Friday. Payment service p99 spikes. Eight agents and one on‑call human, coordinating on a single durable channel that outlives any individual process.

Setup. A platform team registers eight agents with their hub: alert-watcher, triage, db-diagnostician, deploy-historian, patcher, reviewer, postmortem-scribe, and the on‑call engineer jana (a HumanClient, addressable by name like any other participant).

Flow. The watcher opens a consulting channel to jana to confirm the page. Confirmation opens a workflow channel with everyone else. The TransitionGraph routes by tool‑call: triage hands to a diagnostician on investigate_db, diagnostician hands to patcher on propose_revert, patcher hands to reviewer, reviewer hands to jana on needs_human_approval. Jana's approval reverts to patcher, who deploys, then reverts to the postmortem scribe to write the report.

What the network gives you. The channel WAL is the incident log — every envelope, every handoff, every approval, signed and ordered. If the hub crashes mid‑flow, re‑folding the WAL puts the workflow exactly back where it was. If jana drops her laptop on the train, she re‑attaches from her phone by name and her pending turn fires again — same code path as a live notify.

Observed learning. The diagnostician's p50_latency_ms for the db-diagnostics capability drops by 11% after this incident closes. Next time the triage agent picks among diagnostician candidates, that resume is what discovery ranks against.

11 / Demo · cross-hardware, cross-org research

Three machines, two organisations, one channel.

A safety researcher coordinates a frontier‑model evaluation across a laptop, a lab GPU cluster, and a partner organisation's benchmark hub. The same channel handle, the same code, no orchestrator‑in‑a‑box.

Setup. A researcher at a safety institute wants to run a multi‑round adversarial probe of a new model. The probes are designed by a coordinator agent on her laptop (calling a frontier API). Each probe is executed by an evaluator agent running locally on her lab's GPU server (against the model under test, which lives on the same hardware for cost reasons). The benchmark suite is curated by a partner organisation and exposed via their federated hub.

Why federation. The benchmark‑curator agent is at a different organisation, behind their hub. The researcher cannot copy the suite — it's under an NDA. But the agents can coordinate: her hub's HubArbiter resolves "benchmark-curator" to a signed forwarding link to the partner hub. From the channel's perspective, the curator is just another participant.

Why streaming. The evaluator runs a 70B model locally; an evaluation pass takes minutes and produces 4‑8 KB of structured commentary plus inline plots. Token streaming keeps the coordinator responsive; image chunks for the plots ride the same fan‑out. The researcher's notebook renders results as they arrive.

Why durability. The lab GPU is not always online. When it disconnects, the channel stays alive — the WAL persists, the workflow state freezes at the evaluator's turn. When the GPU box reconnects, its inbox cursor replays the unacknowledged envelopes; the evaluator picks up where it left off.

Topology

Three machines, two hubs, one channel spanning all of them. Each participant runs in its own process. The framework's NetworkClient Protocol means the channel looks identical to each.

12 / Position

Where this sits in the 2026 landscape.

The field has converged on a clean two‑layer story — MCP for tools, A2A for the agent wire — but both are resource‑shaped. Action‑driven networking is the missing layer between them and the agent framework above.

Every framework above is, at its core, an in‑process orchestrator that occasionally talks to a remote endpoint. Every protocol is a wire format that two orchestrators agree to speak. Nothing in between treats agent‑to‑agent coordination as a first‑class network primitive with passports, durable channels, declarative protocol contracts, and multi‑hub federation as the base case rather than the extension story.

Sitting alongside resource‑driven networking instead of replacing it: agents in an AG2 channel still call MCP tools; agents at the edge of a federation still expose an A2A surface to non‑AG2 callers. Action‑shaped and resource‑shaped are peer layers, not rivals.

What's actually different.

  1. 01
    Channel as primitive
    The unit of abstraction is the durable, protocol‑typed conversation — not the agent, not the graph, not the team.
  2. 02
    Three‑part identity
    Passport (immutable, signed) + Resume (mutable, observed) + SKILL.md (LLM‑facing). Discovery ranks by outcomes, not names.
  3. 03
    Choreography as data
    TransitionGraph is JSON. The hub re‑folds deterministically. No engine, no DSL, no pickled callables on the wire.
  4. 04
    Liveness over response guarantee
    Declarative protocol‑shape contracts with passive handlers. The framework records, warns, narrows, or closes — never substitutes.
  5. 05
    Trust boundary in the client
    Hub never imports tenant code, never calls Agent.ask. Same surface in‑process and on the wire — by construction.
  6. 06
    Tasks owned by agents
    Hub observes; resumes accumulate evidence; discovery sharpens with use. The orchestrator pattern, inverted.
  7. 07
    Federation is native
    Multi‑hub topology, signed cross‑org passports, peer routing through the same Protocol seam used in‑process.
  8. 08
    Omni‑modal streaming
    Text, audio, image, video chunks share one fan‑out path. View policies demux per‑recipient, per‑modality.

The window.

2026 is the year multi‑agent stops being a demo and starts being deployed. The question is what they're deployed on top of.

The frameworks above are mature enough that the orchestration metaphors are settled. The protocols below are mature enough that wire‑level interop is no longer in dispute. What's open is the layer in between — the substrate on which durable, identity‑bound, choreographed agent‑to‑agent action actually runs. Action‑driven networking is what that layer looks like when drawn intentionally instead of accidentally.
